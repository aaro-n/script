核心概念： 大部分高级参数的值都是 CSS 选择器。它是一种用来在 HTML 文档中定位元素的强大语法。如果你不熟悉，强烈建议先阅读 MDN CSS 选择器教程。
⚠️ 安全配置提醒： 自建 RSSHub 服务需要设置环境变量 ALLOW_USER_SUPPLY_UNSAFE_DOMAIN=true 才能使用 transform/html 路由，否则会返回配置错误。
⚠️ 条目数量限制： transform/html 路由内部硬编码最多返回 20 条。通过 limit 参数可进一步减少，但无法超过 20 条。链接自动补全功能会自动将相对链接转为绝对链接。

基本配置

host

你的 RSSHub 服务部署地址。可以是官方地址，也可以是你自己搭建的服务的地址。

示例：https://rsshub.app

url

你希望为其制作 RSS Feed 的目标网页的完整 URL。

示例：https://sspai.com/matrix

key

如果你在自建的 RSSHub 服务中配置了访问密钥 (Access Key) 以防止滥用，请在此处填写。这是一个可选参数。

示例：my_secret_key_123

limit

限制最终生成的 RSS Feed 中包含的条目数量。值为正整数，可选参数。

注意： transform/html 路由硬编码上限为 20 条，limit 参数只能在 1~20 范围内生效。

示例：15 (表示最多获取 15 篇文章)

mode=fulltext

启用全文抓取模式。勾选后，RSSHub 会尝试访问每个条目的链接，并抓取其页面的正文内容填充到 RSS 的描述中。

  • 这会显著增加服务器的请求次数和处理时间。
  • 当目标网站有反爬虫措施时，可能会失败。

高级路由参数 (routeParams)

title

定义整个 RSS Feed 的标题。如果不填，RSSHub 会默认使用目标网页的 <title> 标签内容。

示例 (CSS 选择器):h1.page-title

item

【最重要参数】用于定位文章列表的范围。你需要提供一个 CSS 选择器，它能够选中 包含每一篇文章所有信息（标题、链接、摘要等）的外层容器。

示例 (CSS 选择器):article.post-item

itemTitle, itemTitleAttr, itemLink, itemDesc, itemPubDate, itemContent

这些参数用来从每个 item 容器内部提取具体信息。它们的选择器是 相对于 item 元素 的。

  • itemTitle: 文章标题。
  • itemTitleAttr: 【新增】 标题在属性中时的属性名。例如当标题存放在 title 属性或 alt 属性中时，设此参数。默认为元素文本。
  • itemLink: 文章链接，通常指向一个 <a> 标签。
  • itemDesc: 文章摘要或描述。
  • itemPubDate: 文章发布日期。RSSHub 会智能解析多种日期格式。
  • itemContent: 【更正】 访问每篇文章的 itemLink 页面，抓取指定 CSS 选择器的正文内容作为全文。RSSHub 会自动缓存抓取结果并使用 sanitize-html 清洗内容（默认保留 <img> 标签）。
示例 (CSS 选择器):
  • itemTitle: h2.entry-title a
  • itemTitleAttr: title (当标题在 title 属性中)
  • itemLink: .post-wrapper > a
  • itemDesc: p.summary
  • itemPubDate: span.date
  • itemContent: article.main-content (详情页正文选择器)

属性提取参数 (...Attr)

当需要的信息不在元素的文本中，而是在其 属性（如 src, href, data-*, datetime）里时，就需要使用这些参数。

itemLinkAttr

指定从 `itemLink` 选中的元素上提取哪个属性作为链接。默认为 href。

场景：链接在自定义属性 data-link 中。
示例：data-link

itemDescAttr

指定从 `itemDesc` 选中的元素上提取哪个属性作为描述。

场景：想用文章封面图作为描述。itemDesc 设为 img.cover。
示例：src (提取图片的源地址)

itemPubDateAttr

指定从 `itemPubDate` 选中的元素上提取哪个属性作为日期。

场景：日期在 <time> 标签的 datetime 属性中。
示例：datetime

其他参数

encoding

当目标网站是老旧网站，使用非 UTF-8 编码（如 GBK, GB2312）导致抓取内容乱码时，可在此手动指定正确的编码。

示例：gbk 或 gb2312

全局 Query 参数（所有路由通用）

以下参数可附加在任意 RSSHub 路由的 ? 后面，对所有路由生效。

过滤参数

  • filter — 正则表达式，匹配标题/正文/作者/分类，保留命中项
  • filter_title / filter_description / filter_author / filter_category — 按字段分别过滤
  • filterout — 正则表达式，匹配标题/正文/作者/分类，排除命中项
  • filterout_title / filterout_description / filterout_author / filterout_category — 按字段分别排除
  • filter_case_sensitive — 过滤时是否区分大小写，默认 true，设 false 忽略大小写
  • filter_time — 仅保留最近 N 秒内的条目，如 86400 = 24 小时
示例：?filter=AI|ChatGPT 保留含 AI 或 ChatGPT 的条目
示例：?filterout=广告&filter_case_sensitive=false 排除含"广告"的条目（不区分大小写）
示例：?filter_time=86400 只保留最近 24 小时

其他通用参数

  • limit — 限制返回条目数量。注意 transform/html 硬编码上限为 20，此参数只能在 1~20 范围内生效
  • sorted — 是否按时间排序，默认 true，设 false 保持页面原始顺序
  • mode=fulltext — 部分路由支持，启用全文抓取。对 transform/html 无效，请用 itemContent 参数代替
  • key — 自建服务的访问密钥 Access Key
  • tgiv — Telegram Instant View 哈希值

📖 详见 RSSHub 通用参数文档

其他 Transform 路由

除了 /rsshub/transform/html，RSSHub 还支持以下 transform 路由：

  • /rsshub/transform/json/:url/:routeParams — 从 JSON API 响应生成 RSS。支持 itemTitle、itemLink、itemLinkPrefix、itemDesc、itemPubDate 等 JSON Path 参数。
    📄 可制作摘要：若 API 返回字段中包含正文，可用 itemDesc 提取。但无法去详情页抓取全文。
  • /rsshub/transform/sitemap/:url/:routeParams — 从网站 sitemap.xml 生成 RSS（:routeParams 可选）。
    ❌ 无摘要/正文：只能拿到 URL 列表和 lastmod 日期，不含页面内容。

详情参阅 RSSHub 官方文档 /rsshub 路由。

制作摘要/全文 RSS 的方式

RSSHub 没有内置通用的 readability 全文提取路由（不存在 /rsshub/fulltext 之类）。以下是目前可用的方案：

  1. /rsshub/transform/html + itemContent — 唯一能去详情页抓取全文的方案。
    指定详情页正文的 CSS 选择器，RSSHub 会自动去每篇文章的 itemLink 页面抓取全文，并用 sanitize-html 清洗（保留 img 标签），带有缓存。需自建服务。
  2. /rsshub/transform/json + itemDesc — 若 API 字段已含正文。
    例如 GitHub Releases API 的 body 字段本身就含完整 Markdown，用 itemDesc=body 即可拿到全文。但无详情页二次抓取能力。
  3. 各路由自带的 ?mode=fulltext — 部分内置路由支持。
    如 bilibili、apnews、caixin 等路由，在订阅地址后加 ?mode=fulltext 即可获取全文。这是路由作者自行实现的，非通用功能。
  4. 第三方 Readability 方案 — RSSHub 社区外方案。
    可使用 RSSHub Radar 配合 Mozilla Readability 等库在前端做全文提取。
